# Isolated developer usability experiment

This is a qualification fixture, never application or runtime-image input.
The outer controller copies a designated scratch workspace into a read-only
`/fixture` mount. Its only editable input is `candidate.c` (UTF-8, regular file,
at most 1 MiB). The independently supplied header and control program remain
in the starter's protected qualification inventory. CLI use requires the explicit
`--demo-workspace` selection; it adds only the named demo target/test to discovery.

`developer_read_pair` reads the first two bytes of a live immutable GBytes in
big-endian order through the checked foundation API. A value receiver is required
and initialized to zero. A NULL or short byte object fails with the foundation
range/input error; the optional error slot must be empty. The function borrows
the input for the call, retains no object and transfers no ownership. Test spans
are initialized. The fixed pair 0x12,0x34 yields 4660, independently of a following
decoy byte. Zero/one-byte objects fail; exactly two and three bytes succeed.

The frozen controller owns automatic GBytes/GError objects and uses unconditional
REQUIRE checks. Its other modes are small debugger controls: synchronized two
worker threads (three total including main), an intentional SIGABRT, normal/7
exits, literal-argument verification, harmless protocol-looking output and a
finite 35-second wait. Intentional signals are debugger experiments only.
Thread state is published under one mutex and condition variable. All created
threads are joined on the normal path. No heap fault or host operation is needed.

Semantic controls include an API declaration/definition/use, comment/string
decoys, separate same-named static symbols and a non-ASCII comment preceding a
queried identifier. Indexing maps `/fixture/candidate.c` to `demo/candidate.c`.
The fixture's actual byte identity is a separate mandatory input alongside the
entire starter identity, included in build state, bundles and qualification/trial
records. A root-only check does not certify this editable input. Its normal
verification is the selected independent test plus the starter's normal checks.
No worker may edit the frozen test/header, protected policy, lock or source inventory.
